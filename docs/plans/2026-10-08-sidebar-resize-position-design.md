# 侧栏宽度变化时的 PDF 重绘与阅读位置设计

## 目标

桌面端侧栏支持拖动、键盘调整、展开和收起。上述操作可以改变 PDF 阅读区宽度，因此页面继续采用现有“适合宽度”布局；但宽度变化不能导致拖动期间反复渲染 canvas，也不能在最终重绘后把阅读位置强制跳到当前页页首。

## 方案

保留 `PdfViewer` 现有的两层性能保护。拖动期间，`App.vue` 通过 `suppressResizeRender` 阻止 `ResizeObserver` 安排渲染，松手后由 prop watcher 统一提交一次宽度变化。侧栏展开、收起、键盘调整和浏览器尺寸变化仍由 `ResizeObserver` 处理，但继续使用 120ms trailing debounce：连续宽度通知只产生一次最终提交。

最终提交宽度前，以旧页面尺寸记录当前视口顶端对应的“页码 + 页内相对偏移”；更新 `viewportWidth` 后只失效并重绘视口附近页面，不调用当前页页首对齐；Vue 完成新尺寸布局后，再根据锚点换算新的 `scrollTop`。这样绝对滚动值会随页面高度改变，但用户看到的内容位置保持不变。页码输入、文档目录导航、显式缩放和旋转仍保留原来的页首对齐语义。

## 边界与验证

- 拖动期间 `ResizeObserver` 必须直接返回，不能启动 canvas 重绘。
- 连续非拖动宽度通知必须清除旧定时器，只在稳定后提交一次。
- 拖动结束与防抖结束必须复用同一个“同步宽度并恢复锚点”函数，防止两条路径行为分叉。
- 单元测试锁定性能门禁、trailing debounce、禁用页首对齐和锚点恢复调用；全量测试与生产构建验证无回归，真实浏览器检查拖动和收展交互。
